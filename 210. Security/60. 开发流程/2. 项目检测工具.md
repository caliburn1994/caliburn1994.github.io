# 开发工具

## 1. 功能介绍

### 1.1. 依赖管理

#### 代码

代码到一定规模，就会涉及切割模块化。不仅如此，我们在开发的时候会使用到各种外部依赖包，以减少代码开发量。而这种外部依赖是需要进行安全检测的。检测工具有：[ Dependabot](https://github.com/dependabot) 

Dependabot 检测到可以升级的依赖，将会创建 MR。而无法升且存在安全问题的依赖，则创建 issue。减少人工检测。 关于 Dependabot 的推荐 [文章](https://github.blog/2022-09-19-5-tips-for-prioritizing-dependabot-alerts/)。

#### 容器/运行环境

如果使用 docker container，其外部依赖的镜像也是需要定期检测的。检测的对象是 Dockerfile，检测工具有：[Dependabot](https://github.com/dependabot)、[Container Scanning](https://docs.gitlab.com/ee/topics/autodevops/stages.html#auto-container-scanning)



### 1.2. 测试

这部分比较难分类，但可以列举以下例子：

- 开发方的测试：常见的有单元测试、集成测试。这些测试既可以是白盒，也可以是黑盒。这种测试往往是为了<u>保证功能的可用性</u>，而较少去关注代码的安全性。
- 第三方白盒测试：[Static Application Security Test (SAST)](https://docs.gitlab.com/ee/user/application_security/sast/) 深度分析代码中存在安全问题。常常是根据字节码进行分析，不需要启动应用也能测试。
- 第三方黑盒测试：[Dynamic Application Security Testing (DAST)](https://docs.gitlab.com/ee/user/application_security/dast/) 会对启动后的应用进行脆弱性检查。



### 1.3. Review

- Code Review Tool：
  - [GitLab - code quality](https://docs.gitlab.com/ee/ci/testing/code_quality.html)：可检测 Code Smells、部分潜在安全问题，并展示出来，方便 Leader 进行 review。Code Review Tool 耗时相对短，适合 Merge Request 使用。
  - [Code Intelligence](https://docs.gitlab.com/ee/topics/autodevops/stages.html#auto-code-intelligence)： 使 Leader 的 review 过程更为流畅与方便的优化工具。

- [Secret Detection](https://docs.gitlab.com/ee/user/application_security/secret_detection/)： 检测代码中是否存在密钥
- [Auto License Compliance](https://docs.gitlab.com/ee/topics/autodevops/stages.html#auto-license-compliance)： 检测是否合法使用软件



### 1.4. 其他

- [Required plugins](https://www.jetbrains.com/help/idea/settings-required-plugins.html)：可以提醒 team 里其他 members 使用哪些软件，以及督促升级。减少沟通的消耗，提高代码和 Intellij 的健壮性。



## 2. 工具选择标准

工具选择按照以下标准为优先选择：

1. 结果尽量在 GitLab 等网页显示，而不需要在本地进行操作
2. 自动化：避免点击按钮就可以得到相关信息。
3. 安全性比较高的。例如 GitHub、GitLab 官方正在使用的
